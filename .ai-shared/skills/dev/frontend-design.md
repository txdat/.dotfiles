# Frontend Design

Use the project's existing design system and component patterns. Establish audience, primary task, information hierarchy, and any material visual direction with the user; record decisions the implementation must preserve.

Design responsive layouts and the applicable loading, empty, error, success, disabled, and focus states. Preserve semantic HTML, keyboard access, visible focus, accessible names, readable contrast, and reduced-motion preferences. Validate forms with actionable errors and retain user input after recoverable failures.

Implement with existing tokens and components before adding variants. Choose typography, spacing, imagery, and motion to support the content and task; no particular aesthetic or signature effect is mandatory.

Verify the actual rendered flow at relevant viewport sizes and interaction states, including keyboard use. Report browser or accessibility checks that could not be completed. Material behavior and visual commitments belong in the plan's acceptance criteria or design decisions.
